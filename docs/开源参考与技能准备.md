# 成都官方招聘聚合网站：开源参考与技能准备

更新时间：2026-09-26
项目阶段：WorkBuddy 正在进行第一轮成都企业池数据收集；网站代码暂不开始编写。

## 一、当前采用的开源参考

### 1. company-career-scraper
仓库：Babak-hasani/company-career-scraper
用途：参考企业招聘系统（ATS）的适配方式。

重点借鉴：
- Greenhouse、Lever、Ashby、SmartRecruiters 等ATS适配器；
- 不同企业招聘系统标识的维护方式；
- 统一职位字段；
- 职位URL和职位ID去重；
- 招聘系统错误、访问失败和结构变化的记录；
- 企业招聘系统更换后的兼容处理。

不直接复制：
- 外部企业名单；
- 与成都项目无关的数据；
- 未确认许可证的第三方内容。

### 2. job-board-aggregator
仓库：Feashliaa/job-board-aggregator
用途：参考大规模职位数据管道和持续更新机制。

重点借鉴：
- 多来源采集流程；
- 职位标准化和去重；
- 每日定时更新；
- 过期职位清理；
- 抓取异常监控；
- 职位数据分片和前端按需加载；
- 使用Common Crawl发现潜在招聘页面的思路。

注意：
- 代码和数据集的许可证不同；
- 不复制其企业数据集；
- 商业化时保留必要的许可证和归属说明。

### 3. Bordful
仓库：craftled/bordful
用途：参考招聘网站前端页面和交互。

重点借鉴：
- 职位列表页；
- 职位详情页；
- 企业详情页；
- 搜索和筛选；
- 响应式布局；
- SEO和JobPosting结构化数据；
- 空状态、加载状态和错误状态。

不直接采用：
- Airtable作为核心数据源；
- 与项目数据模型不匹配的后端逻辑；
- 未确认许可证的图片、图标和文案。

### 4. JobSpy
仓库：speedyapply/JobSpy
用途：仅作为通用招聘数据抓取、字段标准化和异常处理参考。

不作为核心方案，因为它主要面向LinkedIn、Indeed、Glassdoor等第三方招聘平台，而本项目的核心来源是企业官网和官方招聘系统。

## 二、已经安装的Codex Skills

### 1. UI UX Pro Max
安装位置：~/.codex/skills/ui-ux-pro-max
用途：
- 建立网站整体视觉方向；
- 设计搜索和筛选体验；
- 设计职位卡片、企业卡片和详情页；
- 处理移动端响应式；
- 进行可访问性和信息层级设计；
- 减少普通AI生成页面的模板化感觉。

后续使用方式：
先让它产出设计系统，再开始页面编码，不直接让它随意生成页面。

### 2. shadcn
安装位置：~/.codex/skills/shadcn
用途：
- 统一按钮、输入框、筛选器、标签、卡片、弹窗和表格；
- 保持组件变体和交互一致；
- 减少重复CSS；
- 支持桌面端和移动端组件复用。

## 三、暂不安装的Skill

### better-web-ui
暂不安装，原因：
- 它和UI UX Pro Max存在功能重叠；
- 多套完整视觉规则同时启用，可能导致风格冲突；
- 项目第一版先使用UI UX Pro Max建立统一视觉体系；
- 后续第一版页面完成后，再把better-web-ui作为审查和改进工具。

## 四、网站制作阶段的默认技术方向

等WorkBuddy完成第一轮数据收集后，再根据数据格式和数据量确定最终技术栈。目前暂定方向如下：

- 前端：Next.js + TypeScript；
- 样式：Tailwind CSS；
- 组件：shadcn/ui；
- 数据模型：企业、招聘来源、职位、职位快照、职位状态历史、抓取记录；
- 第一版重点：企业列表、职位列表、职位详情、来源验证、最近验证时间、状态筛选；
- 后续再加入：收藏企业、职位订阅、邮件提醒、社交媒体招聘信息。

## 五、进入网站开发前必须完成的准备

1. 接收WorkBuddy生成的企业池文件；
2. 检查企业名称、官网、招聘入口和原始链接；
3. 统一行业分类和企业字段；
4. 确定第一批展示企业；
5. 从企业池中识别Greenhouse、Lever、Ashby等ATS类型；
6. 确定哪些招聘来源可以自动抓取；
7. 确定哪些来源只能人工维护；
8. 根据职位数量确定数据库和更新方案；
9. 设计网站信息架构；
10. 使用UI UX Pro Max生成设计系统；
11. 使用shadcn建立基础组件；
12. 再开始编写网站代码。

## 六、许可证和数据合规要求

- 只借鉴代码结构、数据模型和公开技术思路；
- 不复制第三方网站的企业数据集；
- 不复制企业招聘页面的大段内容作为自己的内容；
- 始终保存原始来源链接；
- 不抓取私人联系方式；
- 对社交平台数据先确认访问规则和服务条款；
- 外部开源代码正式进入项目时，保存其许可证和NOTICE文件；
- 对招聘职位显示“来源企业官网”和“最近验证时间”。
